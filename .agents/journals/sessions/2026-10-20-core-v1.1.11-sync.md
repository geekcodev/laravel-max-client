# Синхронизация с ядром v1.1.11: контакт без `hash` больше не роняет апдейт

## Проблема

Вышел релиз ядра `geekcodev/max-php-client` **v1.1.11** (constraint адаптера — `^1.1.10`). Состав релиза по
release-notes ядра: `ContactAttachmentPayload::$hash` стал терпимым (отсутствие/`null` → пустая строка вместо
`InvalidResponseException`), `Attachment::$filename`, метаданные вложений (`width`/`height`/`thumbnail`/
`transcription`/`size`), rendition-URL видео (`mp4_*`, `hls`), `Subscription::$time`, `Callback::$timestamp`/`$user`
(и фолбэк `callback.user` в `Update::$user`), значение `ChatStatus::Suspended`, обе формы `FailedUserDetails`, снят
`@deprecated` с `addChatMembers()`/`AddChatMembersResult`. Ломающих изменений публичных сигнатур нет, единственная
правка поведения — новое значение enum.

Для адаптера критично первое: до v1.1.11 контакт, отправленный пользователем без подписи, ронял разбор
`Dto\ContactAttachmentPayload`, контроллер вебхука отвечал `400 invalid_payload`, и апдейт терялся целиком.

## Решение

1. `composer.json`: constraint `geekcodev/max-php-client` `^1.1.10` → `^1.1.11`; `composer.lock` пересобран
   (`composer update geekcodev/max-php-client` — установлено `v1.1.11`).
2. `src/Facades/Max.php`: PHPDoc `addChatMembers()` — пометка `deprecated в ядре с v1.1.6` заменена на фактическую
   формулировку ядра v1.1.11 (метод в спеке присутствует, с 9 сентября 2026 ограничен со стороны MAX; пометки об
   удалении нет). Guard-тест `MaxFacadeTest` сверяет только имена и типы возврата, поэтому изменение текстовое.
3. Регрессионные тесты (ядро даёт разбор, адаптер — семантику «подписи нет → телефон неподтверждён»):
   `MaxContactServiceTest::testContactWithoutHashYieldsNoPhone` (пустой `hash` → `null` и `isTrusted() === false`),
   `testContactDecodedWithoutHashYieldsNoPhone` (вложение разбирается из payload реального вебхука через
   `Update::fromArray()`), `testUnsignedContactIsNotTrusted`;
   `PersistMaxUserPhoneListenerTest::testContactDecodedWithoutHashIsIgnored` (payload вебхука без `hash` доходит до
   слушателя, `max_users.phone` не заполняется); `MaxWebhookControllerTest::testDecodesContactAttachmentWithoutHash`
   (полный HTTP-запрос с таким апдейтом отвечает 200, а не 400, и ставит job).
4. Документация: `README.md` — требование к ядру `^1.1.11`, абзац в разделе «Телефон из контакта» о том, что телефон
   берётся только из подписанного контакта, и строка истории изменений; `AGENTS.md` — версия ядра, constraints, факт про
   nullable `hash` в разделе 6.
   `UPGRADE_PLAN.md` — новая строка истории версий.
5. Релиз-ноты `.agents/release/RELEASE_NOTES_v1.2.3.md` (формат `Новое` / `Изменение (BC)` / `Затронутые сценарии` /
   `Качество`); значимое продублировано в README («История изменений»). Релиз адаптера — v1.2.3 (patch после v1.2.2).

## Тесты

382 теста / 959 утверждений, покрытие строк 97.64% (1281/1312). Три новых теста на путь «контакт без подписи» и один
HTTTP-тест на приём такого апдейта.

## Нюансы

- Правило в два состояния осталось прежним: `MaxContactService` без изменений — пустой `hash` и раньше давал
  `ContactVerifier::verify() === false`, поэтому адаптеру достаточно было получить разбор от ядра.
- Изменения ядра v1.1.11, которые адаптер только наследует (без правок): метаданные вложений, `filename`, rendition-URL
  видео, `Subscription::$time`, `Callback::$timestamp`/`$user`, `ChatStatus::Suspended`,
  `FailedUserDetails`. Адаптер не перечисляет значения `ChatStatus` (своя enum реестра `MaxChatStatus` не пересекается),
  `addChatMembers()` не вызывает, `filename`/`vcf_phone` не хранит.
- Обновление `vendor/` потребовало снятия каталога `vendor/geekcodev/max-php-client` под root: файлы, созданные прошлым
  `composer install` из контейнера, принадлежат root и пользователю 1000 недоступны на удаление.
- Интеграционный смоук (`--group integration`) не запускался: в окружении нет `MAX_API_TOKEN`.
