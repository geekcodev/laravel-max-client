# Журнал разработки в git

## Проблема

Каталог `.agents/` был в `.gitignore` под предлогом, что рабочая память процесса не должна попадать наружу. На деле это
отнимало у следующего разработчика и у следующего ИИ-агента то, ради чего журнал и ведётся: после `git clone`
`.agents/` отсутствовал, то есть решения, отвергнутые варианты, раскладку полос миграций, протокол обновления ядра и
подробные release notes можно было получить только от автора лично. Правило «значимое дублируется в `README.md`»
дублировало лишь верхушку, а не нюансы вроде того, почему переименование выполненной миграции ломает ровно те установки,
ради которых делается.

## Решение

`.agents/` отслеживается git. Каталог — рабочая память процесса, а не документация продукта: для внешних потребителей
истина по-прежнему `README.md`, `docs/api-reference.md` ядра и GitHub Release, значимое из журнала дублируется туда.
Правило безопасности прежнее и теперь важнее: каталог видят все, кто клонировал репозиторий, поэтому секреты, токены,
`vcf_info`, телефоны, payload колбэков и прод-ответы в `.agents/` не пишутся (A02, A09).

Правки документации под новое решение:

- `AGENTS.md` §2 — каталог в git, то есть ожидаемая запись в `git status`, а не мусор; §3 — правило 1 требует читать
  карту `journals/JOURNAL.md` в начале работы, чтобы не начинать заново исследованное и не отменять решение без причины
  из журнала; §4 и §4.1 — описание каталога и таблица подкаталогов; gotcha 17 — записи журнала часть репозитория.
- `README.md` — полные описания релизов лежат в `.agents/release/RELEASE_NOTES_*.md` репозитория, а не в рабочем
  окружении.
- `JOURNAL.md` — снята пометка о локальном каталоге.

CI и Gate не затронуты: `php-cs-fixer` ограничен каталогами `src`, `tests`, `config`, `scripts`, PHPStan — каталогом
`src`, поэтому markdown-файлы в анализ не попадают. `.dockerignore` править не нужно: каталог весит 312 КБ и в контекст
сборки попадать не мешает.

## Тесты

Аудит каталога перед добавлением в git: токенов, секретов, телефонов, payload колбэков и ответов реального API не
найдено — в файлах только упоминания имён переменных (`MAX_API_TOKEN` без значения) и правил маскирования. Единственный
идентификатор из реальной базы — `chat_id` группы владельца, он уже опубликован в `README.md`, поэтому добавление
журнала не создаёт нового класса раскрытия.

## Нюансы

Правка меняет границу публичности: то, что раньше нельзя было показать постороннему, теперь видно всем, кто клонировал
репозиторий. Обратного пути у такой правки нет автоматически — если в журнал попадёт секрет, он остаётся в истории git,
поэтому проверка перед коммитом обязательна, а не разовая.

## Gate

Код не менялся, Gate прогнан для изменений предыдущей сессии (миграции и тесты): lint 0 · PHPStan level max 0 · 343
теста / 880 assertion. `composer audit` не гонялся: Packagist недоступен из контейнера.
