# Порядок миграций: полоса `0000_00`

## Что было

Фундаментные миграции назывались `0001_01_01_000001`…`0001_01_01_000003`. Префикс означал «первый после установки», то
есть дублировал то, что и так следует из имени файла, и не говорил ничего о соседях по полосам.

## Решение

Полоса в имени миграции — это позиция владельца в общем порядке, а не отдельный именованный диапазон. Laravel сортирует
миграции приложения и всех пакетов по имени файла и применяет сверху вниз, поэтому внешний ключ допустим только на
таблицу, чья миграция имеет меньшее имя. Раскладка стека i2tech:

```
0000_00 — laravel-max-client: max_users, max_chats, max_chat_users
0000_01 — приложение, системные таблицы (users и прочие)
0000_02 — filament-max-chat
0000_03 — filament-max-broadcasts
0000_04 — приложение, доменные таблицы
```

Адаптер занимает `0000_00` не по привилегии, а по графу: `max_chat_users.chat_id` ссылается на `max_chats` своей же
полосы, а внешние потребители — `users.max_user_id`, `max_chat_messages.max_chat_id` и `operator_id`,
`max_broadcasts.created_by` — ссылаются на его таблицы, поэтому ниже него ничего лежащего не может быть.

Миграции:

- `0001_01_01_000001_create_max_users_table` → `0000_00_000001_create_max_users_table`;
- `0001_01_01_000002_create_max_chats_table` → `0000_00_000002_create_max_chats_table`;
- `0001_01_01_000003_create_max_chat_users_table` → `0000_00_000003_create_max_chat_users_table`.

Во все три добавлен `Schema::hasTable()` в `up()`. Правило §2 `AGENTS.md` переписано: тело выполненной миграции править
нельзя, переименовывать можно — только вместе с guard, иначе смена имени ломает ровно те установки, ради которых
делается.

## Тесты

`tests/Feature/MaxMigrationsTest.php` проверяет по исходникам, что миграции лежат в `0000_00` и что `max_chat_users`
ссылается на более раннюю миграцию своей же полосы. На SQLite нарушение не воспроизводится — таблица с внешним ключом на
несуществующую таблицу создаётся молча, — поэтому проверка идёт по исходникам, а не по результату `migrate`. Сквозную
проверку по миграциям всех владельцев выполняет `MigrationOrderTest` в приложении: подписи всех трёх таблиц адаптера —
публичный контракт, и их совпадение с `MaxSchemaUpgrade` проверяется отдельно в `MaxSchemaUpgradeTest`.
